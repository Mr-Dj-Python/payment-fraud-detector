## Notes / what this proves

- Eviction is correct at the exact boundary, not just "well inside" or "well
  outside" the window — the boundary test is the one most likely to have caught
  a real off-by-one bug if the `<` vs `<=` comparison had been written wrong.
- Counter cleanup on eviction (`del counterparty_counts[key]` once it hits 0) is
  verified directly, not just assumed from reading the code — matches the LLD
  §3.3 requirement that a stale zero-count key must not linger.
- Flagged (not fixed, by design — see `graph_store.py` ponytail comment):
  `graph.accounts` keys are never removed even once an account's own edge deque
  empties, so the dict itself grows with the number of *distinct accounts ever
  seen*, not bounded by the window. Memory-bounded-by-window (HLD §5 N3) holds
  per-account (deque size), not for the account dict as a whole. Not a problem
  at Phase 0's scale; flagged for whoever scales this further.
